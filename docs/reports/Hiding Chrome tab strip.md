# Chrome won't let tabs fully disappear

**Short answer: in a normal Chrome window on a Mac, there is no setting, flag, policy or extension feature that removes Chrome's own tabs completely.** As of November 2026 there are only workarounds. The best one inside Chrome is full screen with "Always Show Toolbar in Full Screen" turned off. The tabs (and the address bar) hide, and come back when the mouse touches the top of the screen. The best one in an ordinary window is Chrome's own vertical tabs squeezed down to a thin strip of site icons. That strip stays on screen. The only way to get zero tabs in a normal window is to switch to **Vivaldi**, which has a plain "Show Tab Bar" on/off switch and installs Chrome Web Store extensions. Windows with no tab strip at all do exist: popup windows, installed web apps, and app or kiosk launch mode. But each of these shows only one page per window, so they don't fit a multi-tab workflow. This matters for Spaces Plus because every competitor has hit the same wall. Arcify says nothing about it. Another extension's help page states plainly that extensions cannot hide Chrome's tab bar. So the realistic product move is to **guide users to the best setup and offer an optional "focus mode"**, not to promise that Chrome's tabs go away.

## Five ways to get closest to "only Spaces Plus," ranked

The table ranks each option by how close it gets to "only the extension's sidebar shows tabs" and by what it costs the user. Steps for each follow below.

| Rank | Option | Chrome's own tabs gone? | What you give up |
|---|---|---|---|
| 1 | Chrome full screen, "Always Show Toolbar in Full Screen" off | Yes, until the mouse hits the top edge | The address bar also hides; the window takes over a whole Mac desktop |
| 2 | Chrome vertical tabs, collapsed to icons, hover-expand off | No: a thin icon strip stays | About one icon's width of screen |
| 3 | Switch to Vivaldi and turn off "Show Tab Bar" | Yes, fully, in a normal window | You change browser; it's unconfirmed whether Spaces Plus's side panel works there |
| 4 | Switch to Brave, vertical tabs set to "hide completely when minimized" | Yes, until you hover the edge | You change browser; Mac support not confirmed |
| 5 | Tab-less windows (popup, installed app, app/kiosk launch) | Yes | Each page gets its own window; no address bar; new tabs open in a normal window |

### Option 1: Chrome full screen with the toolbar hidden

On a Mac, Chrome's View menu has a tick-box called **"Always Show Toolbar in Full Screen."** When it is unticked, full screen hides the tab strip and toolbar. They slide back in when the mouse reaches the top edge ([Google Chrome Help forum](https://support.google.com/chrome/thread/326220798?hl=en); [Chromium design doc](https://www.chromium.org/developers/design-documents/fullscreen-mac/)). Steps: open the **View** menu and make sure "Always Show Toolbar in Full Screen" is *unticked*. Then go full screen with the green window button, View > Enter Full Screen, or Cmd+Ctrl+F. Spaces Plus's side panel or floating window does the tab work. The keyboard shortcuts are muddled. One forum answer calls Cmd+Shift+F "presentation mode." A bug report says Cmd+Shift+F switches the toolbar setting on and off ([Mozilla bug 1702563](https://bugzilla.mozilla.org/show_bug.cgi?id=1702563)). Users should check on their own version. **Unverified:** no Google document says whether Chrome's *vertical* tabs also hide in full screen. Brave's vertical tabs do, under the same setting ([Brave issue #33136](https://github.com/brave/brave-browser/issues/33136)), so Chrome's probably do too. Test it before promising it. Users also report glitches where the toolbar fails to reappear ([Brave community](https://community.brave.com/t/show-navigation-bar-tabs-when-using-fullscreen-immersive-toolbar/281295)).

### Option 2: Chrome's vertical tabs, squeezed to an icon strip

Chrome's own vertical tabs reached stable in **Chrome 147, around April 9, 2026** ([Winaero](https://winaero.com/chrome-147-released-with-vertical-tabs-and-improved-reader-mode/)). One vendor blog says 146 and gives an older Settings label, "Tab strip position" ([SupaSidebar](https://supasidebar.com/blog/vertical-tabs-chrome-mac-2026)). Switching to vertical removes the horizontal strip across the top, which reclaims that row. Steps: right-click a tab and choose **"Show Tabs Vertically."** You can also go to Settings > Appearance > **"Tab position" > "Vertical,"** or tick View > "Show Tabs Vertically" ([Chrome Help](https://support.google.com/chrome/answer/2391819?hl=en&co=GENIE.Platform%3DDesktop)). Then collapse the strip with the arrow at its top, or press **Cmd+Shift+L**. That shrinks it to one icon wide ([PiunikaWeb](https://piunikaweb.com/2026/09/07/chrome-vertical-tabs-expand-on-hover/)). Since about **Chrome 152**, the collapsed strip widens when the mouse passes over it, and this may be on by default. Spaces Plus users will likely find that annoying. To stop it, right-click the menu icon at the top of the strip and untick **"Expand Collapsed Tabs by Hovering"** ([Chrome Help](https://support.google.com/chrome/answer/2391819?hl=en&co=GENIE.Platform%3DDesktop)). The narrow strip never goes away: PiunikaWeb notes Chrome "doesn't hide the sidebar completely" ([PiunikaWeb](https://piunikaweb.com/2026/09/07/chrome-vertical-tabs-expand-on-hover/)). To go back, choose **"Show Tabs Horizontally"** from the same menus. **Unverified:** one secondary source claims a Settings switch called "Auto expand tabs on hover" exists from Chrome 156. Its exact pixel width and that switch are unconfirmed.

### Options 3 and 4: other browsers that hide tabs and still run Chrome extensions

**Vivaldi is the only browser in this research that removes the tab bar completely in an ordinary window.** Untick Settings > Tabs > **"Show Tab Bar"**, or use View > Show Tab Bar ([Vivaldi Help](https://help.vivaldi.com/desktop/tabs/tab-bar/)). **Brave 1.84+** comes second. In Settings > Appearance, turn on vertical tabs and then "hide completely when minimized." Click Minimize Tabs, and the native panel disappears until you hover the edge ([Brave](https://brave.com/whats-new/hide-vertical-tabs/)). Brave staff turned down a request to hide the *horizontal* strip, saying that is "what extensions are for" ([brave-browser #7966](https://github.com/brave/brave-browser/issues/7966)). **Edge's** "Hide title bar while in vertical tabs" hides the title bar, not the tabs. Its Mac support is old and patchy ([gHacks](https://www.ghacks.net/2021/08/06/microsoft-edge-93-hide-the-titlebar-in-vertical-tab-mode/); [MS Tech Community](https://techcommunity.microsoft.com/t5/discussions/edge-vertical-tab-not-working-in-macos/m-p/2210926)). Opera users have asked for the same feature ([Opera forums](https://forums.opera.com/topic/33008/vertical-tabs-or-ability-to-hide-the-default-tab-bar-so-we-can-use-the-vertical-tab-add-ons)). **Unverified and important for Spaces Plus:** whether Chrome's side-panel feature, which Spaces Plus uses, works in Vivaldi. Vivaldi has its own panel system. Also unconfirmed: whether Brave's hide option works on Mac. The developer should test both before recommending either.

### Option 5: windows that have no tab strip

Chrome can open windows with no tabs in three ways. The first is an "Install page as app" window. The second is launching Chrome from Terminal with `--app="URL"`, which gives a window with no address bar, tabs or toolbar ([Kitemetric](https://kitemetric.com/blogs/unlocking-the-power-of-chrome-s-app-flag)). The third is `--kiosk URL`, which is full screen with no browser controls; Cmd+Q exits ([ManageEngine](https://www.manageengine.com/mobile-device-management/articles/chrome-kiosk-mode.html)). Each window shows one site, so these suit a single dashboard and not everyday browsing. Web apps that want their own tab strip ("tabbed mode") have officially shipped only on Chromebooks ([Chrome for Developers](https://developer.chrome.com/docs/capabilities/tabbed-application-mode)).

## Settings, flags and policies offer nothing more

Nothing in Chrome's experimental flags page hides the tab strip in a normal window. The vertical-tab flags (`#vertical-tabs`, `#vertical-tabs-expand-on-hover`) only switched features on early, and they're no longer needed ([ChromeStory](https://chromestory.com/2026/06/how-to-enable-vertical-tabs-in-google-chrome/)). An old Mac flag for full-screen toolbar behaviour, `#enable-immersive-fullscreen-toolbar`, was suggested on Apple Community ([Apple Community](https://discussions.apple.com/thread/255061396)). **It is unverified and may have been removed.** No company-management policy controls Chrome's tab position. Edge has one, `VerticalTabsAllowed` ([Microsoft Learn](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/verticaltabsallowed)). At launch, heise noted it was still unclear whether Google would add policies ([heise](https://www.heise.de/en/news/Chrome-Vertical-tabs-and-improved-reading-mode-11250118.html?view=print)). The full Chrome policy list was not checked, so a new policy could exist. Managed Macs held below Chrome 147 won't see vertical tabs at all. Mac window-manager utilities can't help either, because Chrome draws the tab strip inside its own window.

## Competitors hit the same wall and stay quiet about it

Arcify, the closest competitor, describes itself only as a vertical sidebar. Its documentation and issue tracker say nothing about hiding Chrome's tabs. One issue asks that moving tabs in its panel also moves them in Chrome's real tab strip, which shows users run both side by side ([Arcify GitHub](https://github.com/nisargkolhe/arcify); [Arcify issues](https://github.com/nisargkolhe/arcify/issues?q=tab+bar)). The VertiTab FAQ is the bluntest. It says hiding the tab bar is a "browser design limitation that extensions cannot change," with no workaround ([rabbitpair FAQ](https://www.rabbitpair.com/en/faq/hide-horizontal-tabs)). Tabybara lists tabs in the side panel and leaves the top strip visible ([Chrome Web Store](https://chromewebstore.google.com/detail/vertical-tabs-tabybara/pmkhpefjllhicdhnnnpkobbpbbcflkbe)). Firefox users have a hiding trick through a custom style file, which Chrome doesn't support ([Sidebery](https://github.com/mbnuqw/sidebery)). This means Spaces Plus loses nothing by being honest. A clear setup guide would already beat the competition. Reddit, Hacker News, Workona, Tabs Outliner and similar extensions were not checked.

## What the Spaces Plus developer can build

Chrome's extension toolkit gives no switch for its own tabs. A Chromium contributor said the browser's controls are "immutable" to extensions apart from colours and icons, for security reasons ([Chromium Extensions group](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/nRmF8iz3nG4)). The side-panel feature only *adds* a panel. It can't remove Chrome's tabs. Within those limits, the developer can build four things, ranked by value for effort.

| Idea | What the user gets | Catch |
|---|---|---|
| **Setup guide inside the extension** | A first-run screen or help page with the steps from Options 1 and 2 above, including how to turn off hover-expand | None. Cheapest, and it's what competitors lack |
| **"Focus mode" shortcut** | One key press puts the current window into full screen and back. The toolbar hides if the user has unticked "Always Show Toolbar" | The extension can't change that tick-box itself, so the guide must tell users to. Full screen takes over a whole Mac desktop |
| **"Open as clean window" for a single tab** | Moves a tab into a popup window with no tab strip; Spaces Plus's floating window lists and switches between them | One window per page; no address bar or back button unless Spaces Plus provides them; links that open new tabs land in a normal window |
| **Detect the browser and adjust the advice** | In Vivaldi or Brave, show those browsers' own hide steps | Only worth it if the side panel is confirmed working there |

The full-screen toggle is officially supported. Extensions can set a window to full screen ([chrome.windows API](https://developer.chrome.com/docs/extensions/reference/api/windows)), and a keyboard command can toggle it. The "clean window" idea is technically possible but has sharp edges. Chrome's own documentation says tabs can only be moved between *normal* windows, so moving a page back out of a popup needs a workaround. That workaround is inferred from Chrome's source code and hasn't been tested ([chrome.tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs); [Chromium source](https://chromium.googlesource.com/chromium/src/+/main/chrome/browser/extensions/api/tabs/windows_api.cc)). Three more things are **unverified** and need a hands-on test on a current Mac. First, whether an extension-made popup shows a read-only address bar on Mac; sources disagree ([Chromium Extensions group](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/nRmF8iz3nG4); [Orion feedback](https://orionfeedback.org/d/423-the-popup-window-needs-an-address-bar/24)). Second, whether a popup can hold more than one page. Third, whether Spaces Plus's side panel opens inside a popup at all. Existing "open in popup" extensions are small, with between 2 and 11 reviews ([ExtScope](https://www.extscope.org/extension/gmnkpkmmkhbgnljljcchnakehlkihhie)). An extension that does the opposite, forcing popups back into tabs, has more reviews (21) ([ExtScope](https://www.extscope.org/extension/pnbbookneacpggbngfmhfggennhigonh)). That suggests some users dislike popup windows. Ship it as an opt-in experiment, not the default. One thing is not possible: the "locked full screen" feature is limited to Chromebooks and to Google's own approved extensions ([Chromium test](https://chromium.googlesource.com/chromium/src/+/lkgr/chrome/browser/extensions/locked_fullscreen_window_apitest.cc)).

## Conclusion

The question isn't "how do we hide Chrome's tabs?" Chrome has deliberately put that out of every extension's reach. The useful question is "how do we make the leftover icon strip and the full-screen trick feel intentional?" The leftover strip is about one icon wide. Spaces Plus can win here on guidance and convenience rather than capability. Chrome's new vertical tabs actually help, because they turn the top-of-window strip into a narrow side strip that sits fairly comfortably next to Spaces Plus. Hover-expand recently became the default, so the setup guide should be updated with each Chrome release.

Things to test on a real Mac before telling users anything: whether Chrome's vertical tabs hide in full screen, whether Spaces Plus's side panel works in Vivaldi and inside popups, and whether Brave's hide option works on Mac. **In short: Chrome tabs can be shrunk or hidden in full screen, never removed in a normal window; Vivaldi is the only full escape; Spaces Plus should ship a setup guide and a focus-mode shortcut.**
